## 已完成行为

1. 城市、游玩天数和开始日期统一为多日规划必填字段；缺失字段在登录和任何外部工具调用前合并追问。
2. 字段齐全时默认仍进入小红书模式；`planning_mode` 只作为显式、确定性的模式覆盖。
3. 小红书登录卡片通过可选 SSE 字段声明地图回退能力。用户跳过时，中止旧 SSE、触发后端登录取消
   清理，并在同一会话立即启动地图与天气新流；同一卡片重复点击不会启动多个请求。
4. 小红书正文与天气在登录成功后并行收集；地图 POI/路线与天气在地图模式确定后并行收集。取消会
   传播到子任务，不在登录等待阶段预取天气。
5. 天气只使用高德实际返回并能与行程自然日期精确匹配的预报。部分覆盖、完全未覆盖和调用失败都
   以逐日 `unavailable` 表示，不用当前天气或模型知识补造。
6. 地图链路确定性完成景点过滤去重、两两分日、三餐邻近搜索、最多 17 点距离矩阵、最多 125 个
   三餐组合评分、全程餐厅去重和最终路线模式判定。
7. 每天最多两个景点，输出顺序固定为早餐、上午景点、午餐、下午景点、晚餐。步行仅在距离不超过
   1500 米且耗时不超过 20 分钟时成立；任一超限则查询公交，失败时标记未验证而不伪造路线。
8. 模型只能整理理由、体验方向和天气建议。地点引用、顺序、日期、天气日期和路线端点由服务端严格
   校验；首次失败只允许一次受控修订，仍失败则不输出未经验证的攻略。
9. 最终渲染保留高德 POI ID、地址、类型、搜索词/排名、路线依据、provider、查询时间、天气报告
   时间和警告；小红书模式继续保留原帖子来源与点赞排序规则。

## API、SSE 与数据兼容性

- `ChatRequest.planning_mode` 为可选枚举：`xhs` / `map_weather`。不传时 API 调用形状和默认路由保持
  原行为；未知值返回 422。
- `xhs_login_required` 保持原事件名和原字段，只新增带默认值的 `fallback_available` 与可空
  `fallback_mode`。旧客户端可忽略新字段。
- `login_id` 仅作为既有登录 SSE 协议的短期会话标识在活动流中传递；它不进入助手正文、普通日志或
  PostgreSQL。`xsec_token`、MCP Bearer Token、Cookie 和高德 Key 不进入规划状态、最终输出或数据库。
- 没有 schema 或 Alembic 变更；历史会话与消息读取方式不变。

  测试验证，浏览器级重复点击和竞态仍建议在后续 E2E 中补充。

  保证一般常识描述始终最新。

2. 回滚 `aa657d5` 后不再生成地图结构化攻略。
3. 回滚 `d830334` 后移除地图 POI、餐饮和路线证据收集。
4. 回滚 `3103c03` 后恢复原无开始日期/天气的小红书规划行为。
5. `1325553` 是独立格式提交，可保留；若工具版本要求恢复旧格式，也可单独 revert。

回滚文档不影响运行时。不要使用 `git reset --hard`，以免覆盖工作区中的用户改动。
