# 结构化智能旅游规划平台

## 产品边界

核心规划只接收四类字段：单个目标城市、出行日期、1–10 天时长、可选固定兴趣标签。前端不提交自然语言规划请求，后端不执行需求提取、能力判断、缺失字段追问或交通住宿自动收集。

核心计划包含高德景点、日内顺序、相邻路线、逐日天气、提醒和整体餐饮推荐。餐饮推荐最多三家，不绑定任何一天，也不参与路线、交通耗时或每日景点数量计算。

酒店、航班、火车是三个独立查询。所有参数由用户填写；结构化供应商结果负责事实和链接，LLM 只生成简短摘要。平台不执行预订，前端统一把安全的供应商链接显示为“查看详情”。

## 运行链路

```text
结构化表单
  -> 字段校验
  -> 高德景点与路线 + 天气
  -> 高德餐饮搜索（可选失败）
  -> trip_plan.v2 快照校验
  -> LLM 文案整理（失败时确定性降级）
  -> 用户级计划版本保存
  -> 交互式计划页
```

景点与天气是核心证据；核心证据不可用时规划失败。餐饮服务不可用时，计划仍可成功，页面明确不补造餐厅。

## General Agent

标准聊天请求始终进入 General Agent，不再自动路由到旧自然语言规划图。助手保留模型选择和既有工具，并可在计划页读取当前计划快照作为只读上下文；它没有修改或保存计划的工具，也不得声称已经修改计划。

小红书原帖检索继续使用显式 `planning_source=xhs`，与结构化核心规划互不混合。

## 持久化

`travel_plans` 直接归属用户，聊天会话关联为可空兼容字段。每次生成或重新生成写入不可变 `travel_plan_versions`，并更新计划的当前版本。旧 `trip_plan.v1` 快照继续可读，新规划统一写入 `trip_plan.v2`。
